# ADR 0006 — Tune on TREC CT 2021, report on held-out 2022

- **Status:** accepted
- **Date:** 2026-11-08
- **Affects:** `evals/src/evals/trec.py`, `beacon_core.models.EvalRun`, every number in `README.md`

## Context

Beacon's evaluation rests on the TREC Clinical Trials track. The facts below
were **verified by enumerating the `ir_datasets` registry on 2026-11-08** and
then by actually fetching the files, not taken from documentation:

| | 2021 track | 2022 track |
|---|---|---|
| `ir_datasets` ID | `clinicaltrials/2021/trec-ct-2021` | `clinicaltrials/2021/trec-ct-2022` |
| Topics (synthetic patient notes) | **75** | **50** |
| Qrels | **35,832** — `{0: 24243, 1: 6019, 2: 5570}` | **35,394** — `{0: 28419, 1: 3036, 2: 3939}` |
| Qrels source | shipped by `ir_datasets` (NIST `qrels2021.txt`) | **not shipped** — fetched from `https://trec.nist.gov/data/trials/qrels2022.txt` |
| Corpus | `clinicaltrials/2021` — **375,580 trials** | the **same** snapshot |

Two traps are worth naming because either one silently invalidates every number:

1. **There is no `clinicaltrials/2022`.** TREC CT 2022 reused the April-2021
   ClinicalTrials.gov snapshot, and `ir_datasets` models that by hanging both
   tracks off the 2021 collection. A plausible-looking `clinicaltrials/2022/...`
   ID is a wrong-corpus bug that imports cleanly.
2. **`ir_datasets` 0.6.3 ships no 2022 qrels** — `has_qrels()` returns `False`.
   `evals.trec` falls back to the official NIST file through `ir_datasets`' own
   download machinery, with `QRELS_2022_MD5` pinned so a changed or truncated
   file fails loudly instead of skewing the held-out numbers.

### The qrels are graded, and the grading is the interesting part

`RELEVANCE_LABELS = {0: "Not Relevant", 1: "Excluded", 2: "Eligible"}`.

These are **ordinal, not boolean**: 2 > 1 > 0, and "Excluded" scores *above*
"Not Relevant". A grade of 1 means the trial is topically right for this
patient — right disease, right setting — but the patient fails one of its
eligibility criteria.

So the benchmark itself is asserting that **a right-disease-wrong-eligibility
trial is partially correct retrieval.** That one sentence is what makes Beacon's
metric choices stop looking arbitrary:

- **Retrieval is measured on relevance, not eligibility.** Recall@100 and graded
  nDCG@10 over grades 2 and 1 answer "did the search find the trials that are
  about this patient's disease?" — which is precisely the question a bi-encoder,
  BM25 and a cross-encoder are able to answer. It is also why embeddings being
  unable to compare numbers is not a retrieval bug.
- **Eligibility is the LLM's job, and is scored separately.** Whether a trial is
  *eligible* (2) or *excluded* (1) is the distinction the rule checker exists to
  make, so it is reported as its own eligible-vs-excluded agreement figure
  rather than folded into nDCG.
- **Never collapse the grade to a bool.** Doing so would throw away the only
  label that distinguishes the retrieval question from the reasoning question,
  and would quietly reward a system that retrieves eligible and excluded trials
  indiscriminately. `RELEVANCE_LABELS`' docstring says the same thing in code.

## Options considered

| Option | Verdict |
|---|---|
| **Tune on 2021 (75 topics), report on 2022 (50 topics)** | **Chosen.** |
| All 125 topics, k-fold cross-validation | Rejected. Produces tighter intervals, but every topic has then been seen by the tuning loop, so there is no held-out claim left to make. |
| Random split of the pooled 125 topics | Rejected. Weaker than the natural split and strictly worse: pooling first is itself the leak, since choosing the split after seeing the pool invites reshuffling until the numbers look good. |
| Tune on 2022, report on 2021 | Rejected. 2021 has more topics and more positive judgments (5,570 eligible vs 3,939), so it is the better *tuning* set; and the larger set makes the sweep less noisy where noise does the most damage. |

## Decision

**Everything is tuned on 2021. The headline is measured on 2022, once.**

Tuned on 2021 only — each of these is a `RetrievalSettings` field precisely so
that an ablation is a config change rather than an edit:

- `query_count` (N generated queries), swept over {1, 3, 5, 10}; N=1 doubles as
  the "does LLM query generation help at all?" ablation row
- `rrf_k` (60), `fuse_top_k` (100), `rerank_top_k` (20)
- `use_rerank`, `apply_age_sex_filters` — the latter is allowed to come out
  *negative*, because the filter is only as good as the age parsing
- prompt wording, effort levels, and the final scoring formula

Reported from 2022 only. **No number measured on 2021 may be published as a
result.** 2021 figures appear in this repository only as tuning curves,
explicitly labelled as such. Every run is recorded in the `eval_runs` table with
its split, so which number came from where is a matter of record and not of
memory.

## Consequences

- **Fifty test topics is not many, so confidence intervals are mandatory, not
  decorative.** A 2-point nDCG difference on 50 topics is very likely noise.
  Bootstrap CIs and paired significance tests (both in `ranx`) accompany every
  reported figure; the README tables carry a CI column, currently
  **{nDCG@10 ± CI}** and friends, and a difference without an interval is not a
  result.
- **There is effectively one shot at 2022.** Every look at the held-out split
  spends some of the claim's value, so each configuration is run against it once
  and the output is archived in `eval_runs`. The temptation to "just check" after
  a tweak is the failure mode this ADR exists to prevent.
- **The CI regression gate runs on neither split's headline.** It uses a small
  (≈10-patient) subset with recorded LLM responses, so it is free and
  deterministic; it protects against regressions, it does not produce results.
- **The 2022 qrels are a live external download.** If NIST moves or changes the
  file, evaluation stops working rather than quietly producing different numbers
  — that is what `QRELS_2022_MD5` buys, and it is the right trade.
- **Both tracks share the April-2021 corpus snapshot**, so the trial set is
  identical across tune and test. That is a feature for this split — the only
  things that differ are the topics and the judgments, which is exactly the
  generalisation being claimed. It is also a stated limitation: the trial
  snapshot is years old, and nothing measured here says anything about today's
  ClinicalTrials.gov.
- **Fairness slices are reported on the held-out split too**, by patient age
  group and sex, because an aggregate number can hide a system that works for
  some patients and not others. Those figures are
  **{fairness_slice_age}** / **{fairness_slice_sex}** — not yet measured.
